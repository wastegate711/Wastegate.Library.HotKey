# Wastegate.Library.HotKey

![Логотип Wastegate.Library.HotKey](Images/west.png)

Платформенно-независимая библиотека для регистрации сочетаний клавиш и вызова связанных с ними обработчиков. Целевая платформа — .NET Standard 2.0.

## Использование

Создайте `HotKeyManager`, зарегистрируйте сочетание и передавайте ему события клавиатуры из вашего UI-фреймворка. `TryHandle` возвращает `true`, если сочетание зарегистрировано, и вызывает обработчик. Регистрация снимается через `Dispose`.

```csharp
using System;
using Wastegate.Library.HotKey;

var hotKeys = new HotKeyManager();
var save = hotKeys.Register(
    new HotKeyGesture(ConsoleKey.S, HotKeyModifiers.Control),
    () => SaveDocument());

// В обработчике клавиатуры приложения:
var handled = hotKeys.TryHandle(
    new HotKeyGesture(ConsoleKey.S, HotKeyModifiers.Control));

// При завершении работы:
save.Dispose();
hotKeys.Dispose();
```

Доступные модификаторы: `Alt`, `Control`, `Shift` и `Windows`. Одно и то же сочетание нельзя зарегистрировать повторно одновременно. Обработчики вызываются вне внутренней блокировки менеджера; исключения из обработчиков передаются вызывающему коду.

Библиотека не перехватывает ввод операционной системы и не регистрирует глобальные системные горячие клавиши: приложение передает ей уже распознанные события клавиатуры.

## Описание API

### `HotKeyModifiers`

Флаговое перечисление модификаторов клавиатуры. Значения можно объединять с помощью побитового ИЛИ:

- `None` — модификатор отсутствует.
- `Alt` — клавиша `Alt`.
- `Control` — клавиша `Control`.
- `Shift` — клавиша `Shift`.
- `Windows` — системная клавиша Windows.

### `HotKeyGesture`

Неизменяемая структура, описывающая одно сочетание клавиш.

- Конструктор `HotKeyGesture(ConsoleKey key, HotKeyModifiers modifiers = HotKeyModifiers.None)` проверяет корректность клавиши и набора модификаторов.
- Свойство `Key` содержит основную клавишу сочетания.
- Свойство `Modifiers` содержит примененные модификаторы.
- Метод `Equals` сравнивает клавишу и модификаторы; `GetHashCode` предоставляет согласованный хеш для словарей и коллекций.
- Операторы `==` и `!=` обеспечивают удобное сравнение значений.
- Метод `ToString` формирует читаемое представление вида `Control+S`.

При передаче неизвестной клавиши или модификатора, не входящего в перечисление, конструктор выбрасывает `ArgumentOutOfRangeException`.

### `HotKeyManager`

Основной потокобезопасный контейнер зарегистрированных сочетаний.

- `Register(HotKeyGesture gesture, Action handler)` проверяет обработчик, состояние менеджера и отсутствие уже зарегистрированного сочетания. При успехе возвращает объект `HotKeyRegistration`.
- `TryHandle(HotKeyGesture gesture)` ищет сочетание по переданному gesture. Если зарегистрированная привязка найдена, метод вызывает обработчик вне внутренней блокировки и возвращает `true`; при отсутствии привязки или после освобождения менеджера возвращает `false`.
- `Dispose()` снимает все привязки и переводит менеджер в освобожденное состояние. Повторный вызов безопасен.
- Исключение `ArgumentNullException` выбрасывается для отсутствующего обработчика.
- Исключение `InvalidOperationException` выбрасывается при повторной регистрации того же сочетания.
- Исключение `ObjectDisposedException` выбрасывается при попытке регистрации после `Dispose()`.

Все обработчики вызываются последовательно в том потоке, в котором был вызван `TryHandle`. Исключения обработчика не перехватываются и распространяются вызывающему коду.

### `HotKeyRegistration`

Представляет конкретную привязку сочетания к обработчику.

- Свойство `Gesture` возвращает сочетание, переданное при регистрации.
- Метод `Dispose()` снимает только эту привязку из родительского менеджера. Повторный вызов безопасен и не затрагивает другие привязки.

## Пример работы

```csharp
using System;
using Wastegate.Library.HotKey;

using var hotKeys = new HotKeyManager();

HotKeyRegistration saveRegistration = hotKeys.Register(
    new HotKeyGesture(ConsoleKey.S, HotKeyModifiers.Control),
    () => SaveDocument());

bool handled = hotKeys.TryHandle(
    new HotKeyGesture(ConsoleKey.S, HotKeyModifiers.Control));

saveRegistration.Dispose(); // Снять только привязку сохранения.
```

## Сборка и публикация

- Pull request в `dev` запускает сборку и упаковку NuGet-пакета с dev-версией. После успешной сборки workflow создает prerelease в разделе **Releases**. Для каждого обновления PR создается отдельный prerelease.
- Push в `release` собирает пакет стабильной версии, создает GitHub Release и публикует пакет в NuGet.org.
- Для публикации в NuGet.org добавьте в настройках репозитория GitHub Actions секрет `NUGET_API_KEY` с API-ключом NuGet.org.
- Чтобы автоматически создавать dev-релизы, workflow `publish-dev-release.yml` должен быть доступен в ветке по умолчанию (`master`); PR-сборка запускается после появления `build-pr.yml` в целевой ветке `dev`.

## Gitflow

- `master` — стабильная ветка.
- `dev` — интеграционная ветка; изменения поступают через pull request.
- `release` — подготовка стабильной публикации; каждый push в эту ветку публикует новый пакет.
- Рабочие ветки создаются от `dev` и вливаются обратно через pull request. Подготовленный релиз переносится в `master`; после релиза изменения синхронизируются обратно в `dev`.
